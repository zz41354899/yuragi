# Momo: character identity to web interaction

Optional historical case from Kirameki Catch. The migrated case used source snapshot `110e983209c53b21091879b1906c70c6791a642e`; do not infer the current repository or deployed site from it. Installed skill users do not need the Momo project or artwork to create their own character.

The example connects a moon-rabbit singer/dancer identity, a recognizable twin-tail/ear silhouette, expressions, a participation invitation and character-related completion feedback. These are questions to explore in an original character, not a required story, game or reward checklist. Keep character palette distinct from interface functional colors.

Image-based pose sequences plus web transitions do not imply a hand-drawn high-frame-rate animation. Shared-surface deformation keeps the source texture connected but cannot invent new viewpoints, eye/mouth layers or hidden pixels. Yuragi's Momo preset demonstrates one humanoid binding; it is not a reusable coordinate template for other shapes.

Read source files only when verifying this case. If links cannot be accessed, label external verification unavailable and continue with the general design questions. Do not create empty copies of case paths in the user's project.
