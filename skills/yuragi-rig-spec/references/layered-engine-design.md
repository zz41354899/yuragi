# 分層引擎使用注意事項

更新日期：2026-10-04。適用於本機 v2 分層播放器與素材建置流程。

Yuragi 已能繪製獨立附件、套用父子變換、局部彈簧、共享接點、圖集與靜態 alpha 遮罩。角色能否完成預期動作，還要看素材是否完整、綁定是否合適，以及實際畫面是否通過驗收。

## 1. 先確認模型與播放器版本

| 模型 | 播放器 | 素材與適用範圍 |
| --- | --- | --- |
| v1 RigModel | createPlayer / YuragiCharacter | 完整原畫的共用表面；海月、眼神與參數動畫使用這條路徑。 |
| v2 LayeredModel | createLayeredPlayer / YuragiLayeredCharacter | 明確製作的獨立附件、圖集與綁定資料。 |

兩種模型不能直接互傳。v1 的 parts、pointerGroups 或裁出的 PNG，不能直接視為可播放的 v2 附件。v2 目前沒有 v1 的 gaze、動畫或 pin APIs；需要這些功能時先確認整合方式。

## 2. 裁出部件後，檢查遮擋區是否需要補圖

頭髮移開肩膀、袖子離開手臂或裙片擺動時，原先被遮住的位置可能會露出。只有可見裁片的素材會缺少這些像素，必須由作者提供補圖並記錄來源。

每件附件都要標示 coverage 與 provenance。build_layers.py 預設拒絕 visible-only；--allow-visible-only 只供原型測試，不代表補圖完成。

目前海月示範仍是 visible-only：可以檢查小幅動態、繪製與綁定，但尚未完成補圖後的大幅動作驗收。

## 3. 持物與柔性部件分別綁定

握傘手、傘柄與傘面等同一硬物組，使用同一剛性節點，避免各自的彈簧使接觸位置漂移。需要跨附件對齊的接點，引用同一個 joint，保持相同座標與權重。

髮束與布料的根部跟隨父節點，末端再逐步加入局部彈簧權重。先確認根部不滑動，再增加擺動幅度。若反向時出現拉伸、折疊或露洞，先修素材、接點或權重。

## 4. 保留來源位置與遮擋順序

attachments 的陣列順序就是繪製順序。前髮、身體、衣料、後髮要按實際遮擋關係排列；不能為了少一次 draw call 重排。

bounds 使用整張來源圖片的座標，rect 使用圖集像素。替換裁片後要保留其來源位置並確認尺寸；裁切或縮放素材後，需要更新對應資料。

遮罩目前只支援同一圖集中的靜態 alpha 圖，會隨附件網格一起變形。遮罩要有明確 alpha 通道；巢狀遮罩、動態附件遮擋與即時附件交換尚未提供。

## 5. 模型驗證與畫面驗收分開記錄

validateLayeredModel 通過，表示模型結構與數值符合契約。Python 建置另會在九個游標位置取樣，檢查網格翻折與共享接點。這些檢查仍不能代替素材的視覺驗收。

交付前至少檢查：

- 中立姿態能還原原畫，比例與接縫沒有改變。
- 上下左右、四個角落與快速反向時，沒有露洞、重複線或異常遮擋。
- 持物接點與柔性根部保持穩定。
- 減少動態時保持正確靜態畫面；載入失敗時有完整原畫備援。
- 暫停、重設、取消載入、離開頁面與觸控取消都正常。

完成實際檢查後才記錄 visualAcceptance。海月目前來源尺寸的中立合成誤差為 0；共享 joint 的精確接縫另以合成 fixture 驗證。這不代表所有縮放、裝置與大幅動作均已通過。

## 6. 效能數據要標明測量範圍

分別量測 CPU 更新、GPU 繪製、draw calls、圖集記憶體、載入與遮罩成本。播放器顯示的 CPU 時間包含更新與繪製提交，不包含 GPU 完成時間。

目前海月原型有 255 頂點、436 三角形、1 次繪製與 16 MiB 解碼圖集。這是此模型的數據；實體手機、GPU 計時與跨框架比較仍未測量，不能據此宣稱優於 Live2D、Spine 或 Rive。

## 7. 確認尚未提供的功能

IK、骨骼約束求解、Spine 匯入、多動畫混合、blink／mouth 附件參數、動態遮罩與大角度轉身尚未實作。需要這些效果時，先確認所需素材與引擎功能。
